## 再現した問題と修正

1. 既知の商品種類で商品名の数値候補があると、説明文の具体的な使用内容を候補比較へ入れずに確定していた。既存safeCaptionCandidatesと同じ安全条件を通る説明候補も、既存の意思決定kernelで商品名候補と比較する。出典をitemCaptionのまま保持。サイズだけ・高リスク文・HTML断片は候補にしない。合成例「収納ボックス30L」に原文「収納ボックスには毛布を収納できます。」があれば、容量数値だけでなく実際の収納内容を引用する。商品別分岐・新しい生成器は追加しない。
2. 説明候補の否定検査が「できない」を除外しても「できません」「出来ません」を除外していなかった。両表現を除外。無関係な別商品・保証・否定・寸法だけの文が正当な商品名候補を押しのけないことを確認する。
3. 候補比較の初回検証ではサイズだけの説明がIHの使用理由を押しのけ、既存の未見商品テストが失敗した。既存のサイズ単独拒否を比較前に適用した。テストの期待値は維持。また「ストレスフリー」「抜群」を含む販促文を除外し、根拠ある従来候補へのフォールバックを維持する。
4. quoteBoundaryValidは原文中の先頭出現だけを見るため、後ろに完全な品名があっても境界不一致となった。既存の境界文字集合を変えず、各出現を検査する。これにより商品種類検証の取りこぼしは解消するが、別の分類競合を解除したり完成文に強制昇格したりしない。
