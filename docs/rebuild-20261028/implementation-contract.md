# ウレナビ再構築・実装契約 v1

2026-10-28 JST。基準 f6f6c95b2e5322e872b2db8ab02b7c5bb4c3ddad。
P1の仕様を固定する文書。P0未成立のため実装未着手。実装済み・容量成立の主張ではない。

## 不変条件と境界

モデル openai/gpt-oss-120b、各通信出力上限3000、最大4通信、書き直し1回。
429・使用量不明・残予算不明・保存失敗後の自動再送なし。
外部完成結果は product{what,acts_on,acts_on_quote} と sentences[{text,kinds,quotes}]。
内部計画は外部完成結果へ混入させない。既存安全性検査を呼び出し、緩和しない。
本番ルート・UI・認証・決済・DB/RLS・既存データは変更しない。
新版は明示指定したローカル実験実行器だけから呼ぶ。既存ルートが既定、新版撤回は実験呼出の停止だけで完了する。

## 保存原文

入力は保存済み itemCode/itemName/itemCaption/catchcopy。元の文字列と各フィールド境界を保持。
原文hashはフィールド名・値を固定順でUTF-8 JSON化したSHA-256。itemCodeも別に記録。
長すぎる入力を切り詰めず capacity_insufficient で停止。否定・条件の省略は禁止。
引用は {field,start,end,text}（UTF-16位置、半開区間）。text===original[field].slice(start,end) を機械照合。
正規化した比較表現を使う場合も、原文位置への対応を保持し、原文そのものを上書きしない。

## 最小内部表現

| 要素 | 必須情報 |
|---|---|
| sellingProduct | 本体ID、商品種別、利用者、用途、作用対象、根拠引用、判定 |
| feature | 特徴ID、具体的内容、所有者ID、根拠引用、判定 |
| owner | 本体/部位/付属品/関連商品/モデルの種別、所属先、根拠引用、判定 |
| scope | モデル・サイズ・色・種類、対象、部位、適用条件、否定、程度、数値単位、根拠引用 |
| intention | 用途/機能を使う意図/好み/内容の選好/仕様上の適合、内容、対象者・場面（必要な場合のみ） |
| relation | 特徴ID、意図ID、意味関係、関係全体を支える引用、どこまでが意図か、保証していない結果、判定 |
| sentenceBinding | 文ID、使った特徴・関係ID、連続引用、全ての事実節の対応 |
| verdict | supported / unsupported / unclear、具体的理由、失敗した要素ID |

共有語・商品名一致は引用候補の探索にのみ利用し、所有者や意味関係の合格根拠にはしない。
relationの意味関係は「用途への機能適合」「使い方・操作の適合」「味・見た目・素材等への選好適合」「収録内容・構成への関心」「具体的な対象と仕様の適合」。ジャンル名や商品名の例外分岐は禁止。
意図は仮定として表現できるが、効果や成果は原文の明示的裏付けを別に必要とする。
数・素材・一般用途への「便利」の付加、特徴の言い直しだけではrelationをsupportedにしない。
食品・本・装飾品にも同じ構造を使い、悩みや機能効果は要求しない。

## 4通信の責任

1. 初稿生成通信：同一の構造化応答の内部計画でA商品理解→B特徴・意図・関係の選択→C本文を順序固定して作成する。計画を先に出力し、引用から本文への対応を保持。新しいAI工程は増やさない。
2. 初稿検証通信：原文全文・内部計画・本文全文を渡す。全文・全文章の対象、部位、条件、否定、程度を検証。引用・数値単位・本体を含む事実検証と、独立した品質6軸を別に判定。計画がsupportedでも本文を免除しない。
3. 書き直し通信（必要時のみ）：失敗ID、事実節、誤った意味関係、表現、修復目的、維持すべき確認済み事実を渡す。保持するのは事実・条件であり、前の文章への執着ではない。新しい主張には同じ根拠契約を適用。
4. 再検証通信：初稿と同じ全検証。失敗した箇所だけの部分審査は禁止。未解消なら未完成で終了。

機械検査で落ちた場合はAI検証へ送らず、必要なら3へ進むので通信数は減る。どの経路でも上限4。
内部応答の計画と完成結果を分けるためwriterの内部schemaを改訂するが、公開APIのproduct/sentences契約は維持。
上記内部表現を3000以内へ収められる証拠は未取得。収まらなければ省略で取り繕わず未完成にする。
入力・system指示・schema・最大出力を含む送信前容量判定を各段階で実行。全段階が成立する見込みなしに開始しない。

## 完成条件

機械検査通過は合格証明ではなく、拒否条件に該当しないという意味のみ。
AI事実審査の全欄supported、品質6軸の全欄pass、引用の完全照合を同時に要求。
品質6軸は「商品理解」「特徴の具体性」「選ぶ理由」「対象・場面・価値」「自然さ・魅力」「根拠外主張なし」。各欄に本文箇所・引用・理由を必要とし、unclearや欠落は不合格。
原文に販促表現が存在しても、効果・保証・優位性・購入理由の合格根拠にはしない。
同じモデルによる検証は運用上の検証であり、Claude盲検・ヒロ目視の代替にはしない。

## 失敗状態（主状態＋複数の詳細理由）

| 状態 | 定義・処理 |
|---|---|
| source_insufficient 原文不足 | 保存原文自体に本体・具体的特徴・関係の必要根拠がないと確認できる。AIの空欄や抽出失敗だけでは分類しない |
| product_misidentified 商品誤認 | 原文にある本体・所有者・モデルと解釈が一致しない、または根拠はあるが解決できない。後者はdetail=understanding_unresolved |
| choice_relation_invalid 選ぶ理由不成立 | 特徴と意図の関係が不成立・一般論・言い直し。原文不足とは別 |
| fact_mismatch 事実不一致 | 本体、対象、部位、条件、否定、程度、引用、数値単位の不一致 |
| quality_insufficient 品質不足 | 事実が合っても6軸のいずれかが不合格・不明 |
| throughput_insufficient 処理能力不足 | RPM/RPD/TPM/TPD、共有枠や利用者割当が運用目標を満たさない |
| capacity_insufficient 容量不足 | 原文と契約を保持した単一通信の容量・出力上限が成立しない |
| transport_or_storage_failed 通信・保存失敗 | 429、usage不明、送信応答不明、保存失敗をsubtypeで区別。sent/unknownを記録して自動再送しない |

複数失敗時は通信・保存→容量→処理能力→本体→事実→関係→品質の順に主状態を決め、全詳細を保持。
原文不足は根拠不存在が確認できた場合だけ。モデルが理解できなかったケースを母数から除外しない。

## 保存・再利用・隔離

実験専用ファイルだけへ保存。実験実行器にはDB関数、既存キャッシュstore、認証・決済モジュールを渡さない。
P3-Aではネットワーク全面拒否を既定にする。P3-Bで別途承認された場合のみGroqの1エンドポイントを許可し、他のHTTPは拒否。
組織枠はファイル名やAPIキーでは隔離できない。承認時に他用途の消費と予約を含む組織全体の残枠を確認し、専用の有限予算を先取りする。確認不能なら停止。
生成前に実験専用ディレクトリへ排他取得・送信予約を永続化し、送信済み印を先に記録。プロセス消失後のsent/unknownは再送しない。
キャッシュキー=原文hash＋モデル＋設計版＋生成条件＋検証版＋安全性版。全てが一致した完成結果だけ再利用。
失敗・usage不明は再利用しないが送信抑止台帳に残す。同じキーをrunKeyの変更で無意味に再生成しない。
新旧保存先を分離し、旧版readyを新版完成へ移行しない。新版の初期キャッシュ命中はゼロとして容量計画を立てる。

## P3の固定ルール

P3-Aは実装後に実施。既存契約・安全性・上限4・429停止・重複防止・usage不明停止・DB書込禁止・旧キャッシュ隔離を拒否例と正常経路で検証。成功を文章品質改善とは呼ばない。
P3-Bは予定通信数・最大トークン・共有枠影響・停止閾値を実装の実際のpayloadで算出して提示し、別途明示承認後のみ実行。20商品、合計80通信、旧版再生成も合算。
旧版原文との一致が完全に確認できない商品は比較に数えない。説明が同じでもcatchcopy不明なら条件一致とはしない。
評価20件の原文・良文/弱文/安全負例の区分・ジャンル・旧出力・生成条件を送信前に凍結。未見120件は触らない。
実送信のattempt ID、商品ID、原文hash、送信数、入出力tokens、時間、HTTP状態、完成状態、書き直し結果を追記保存。
Claude用には商品ID・ジャンル・原文全文・A/Bのみ。暗号学的乱数で新旧割当を作り、対応表は別ファイル。欠落・未完成を完成文として埋めない。
6軸個別pass/fail、A明確/B明確/同等/判定不能、根拠・理由・重大な根拠外主張の有無を記録。
ヒロの抽出10件はモデル結果を見る前に固定。ヒロ判定で上書きせず別欄に残し、最終判定ではヒロを優先。重大主張の不一致は保留。
評価可能20件、新版勝ち11以上、既存良文悪化0、重大根拠外0、安全性緩和0、予算遵守の全条件必須。20件未成立は保留。
