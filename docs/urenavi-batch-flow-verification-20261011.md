# 一括投稿文準備の操作修正

生成中・検証待ちに候補ボタンを再度押すとrenderが結果Mapとgenerationを初期化する一方、既存キュー実行中のため新キューは起動できなかった。候補準備入口で進行中・pending・pausedを検出し、現状を保持して確認・再開へ案内する。開始直前に投稿済みと同じ商品ID/URLの重複を除き最大3商品にする。

本人操作による停止・再開を追加。停止は現在の商品が終わった時点、または商品間待機後の次送信前に未処理商品をpausedへ移す。完成済み結果は保持。再開はpausedのみを対象としdoneは再送信しない。pending商品の検証を先に行う。429/upstreamStatus429が含まれる同じ一括生成は再開を拒否する。自動再試行は追加していない。生成契約・品質基準・AI使用条件は変更しない。

画面関数をVMで実行し、連打時の結果保持、投稿済み除外、同一商品URL/code重複排除、最大3件、停止→再開、429と停止同時発生、再開ボタンのpending/429拒否を確認。DOMスタブであり実機検証ではない。無料Groqへの実通信は実施していない。

未解決：認証後iPhone実操作・実商品生成品質、楽天の商用データ供給許可、無料Groq処理量と採算実測。許可された開発ブランチとPreviewのみを変更する。

## 通常検索による進行中の結果置換

通常検索がrenderでgenerationを更新しても、既存aiQueueRunningのため新しい一括生成が起動できない経路があった。通信中は新検索を送らず、現在の商品を終えて停止する操作へ案内。pending/pausedから別検索を始める場合は、一括生成終了を明示的に確認し、拒否なら現在結果を保持。コピー済み・投稿済み台帳は検索結果とは別に保持する。429の自動再試行は追加しない。

全373テストとvercel-build成功。通常検索の実ハンドラ入口をVM実行し、通信中の拒否と確認待ちの破棄拒否を確認。ブラウザ認証・iPhone実操作は未確認。
