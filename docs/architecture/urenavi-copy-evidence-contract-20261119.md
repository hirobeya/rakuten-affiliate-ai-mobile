# ウレナビ｜文章生成中核の再構築契約（2026-11-19）

## 目的
日本語の魅力的な購買理由と原文根拠の両立。PR #184の既存認証・決済・無料枠・iPhone動線・共有レート制限は保護する。既存の商品別正規表現を増やして合格件数だけを上げることは禁止する。

## 責務を5工程に分離（既存関数の境界を採用）
1. Source intake: Rakutenの商品名、説明全文、売り物の選択肢、仕様、条件、価格。販促・関連品・断片の混入を拒否。説明が欠ける商品を「AIで補完可能」とみなさない。
2. Evidence ledger: `source-evidence-ledger.js` は購入判断に使えそうな*商家の原文を一字一句*、原文の文字位置と商品との結び付きで記録する。候補にpublic approval権限なし。全否定・別売・販促・安全断定は除外し、既存 `reviewSourceBenefit` を共通使用。未知はnull/未確認を維持。
3. Decision: 1つの購入理由を「対象/使用場面/特徴/理由/根拠」の有向関係として確認する。連続した別々の根拠から勝手な因果を合成しない。根拠が商品に紐付かない場合は送信前停止またはAI検証対象。
4. Writing: verified relationの意味を変えず、自然な日本語に組み換える。定型文の過剰な反復・カタログ・強い断定を禁止。まず独自エンジン、必要時のみ有界Groq。生成文は候補であり、まだ公開不可。
5. Independent veto: 対象/特徴/条件/否定/数値/原文との対応を検査。6軸品質（理解・具体性・購入理由・対象場面・自然さ・原文外0）は別の評価。GitHubテスト成功は編集評価合格ではない。

## 44商品実測と優先度
`tests/copy-44-root-causes.test.js`：現行の後段診断で、`purchase_reason:no_grounded_purchase_candidate` 15、`purchase_reason:repeated_use_and_identity_only` 1、`extraction:no_grounded_facts` 7、`quality:catalogue_only_copy` 5、`identity:identity_unresolved` 1等。
`tests/source-evidence-ledger.test.js`：同じ44商品を厳格な追加証拠抽出に通すと、原文に位置を付けて抽出できた商品4、購入理由となる直接関係2。これは「そのほかの商品に原文がない」意味ではない。抽出基準のカバー率が低く、単純に生成許可すると不正確な投稿が増える危険性を示す。
現行コピー監査候補9。候補≠検証済みの販売品質。たとえば旧ペットベッドの不適切な角括弧引用は出版許可しない。

## 今後の変更の前提条件
- 44商品を「情報欠損」「商品主体が不明」「原文の関係抽出失敗」「関係構築失敗」「文章表現不合格」「根拠不一致」に分類。原因に対応する工程のみ変更。
- 各変更の前に再現例＋反証例をテストへ追加。44商品に加え別カテゴリでも同じルールを適用。
- メッセージの便利さや購買動機を根拠なしに追加して通す変更は禁止。
- 増えた候補はすべて実際の文章を人が確認し、他の商品の回帰を通過すること。
- 投稿不可の正しい拒否を失敗件数に数えない。情報取得が欠ける場合は原文の完全性を先に回復。
- 実Provider通信、新たな請求、main/Production、本番Supabase変更なしでローカル・GitHub無料CIを完了してから別承認境界へ。

## 現時点の状態
証拠中間表現は実装・単体テスト・44商品監査に統合済みだが**公開用の文章生成器にはまだ接続していない**。目的は安全に原因を見える化し、次の変更が商品ごとの場当たり的な例外とならないようにすること。
