基準コミットは `51537a0375fd3dcfa2e14829d5dcefa1d49c9e2a`。販売保留。

## 商品の入力とデータ経路

- `public/app.html` に商品名・特徴・説明・任意の価格を入力し、生成結果をコピーする画面を追加。Previewではオーナー、商用候補の手入力モードでは認証した契約アカウントが対象。
- `/api/manual-room-copy` は許可した4入力をローカルエンジンだけに渡す。商品IDやURLは使用せず、検索・商品取得・商品キャッシュ・生成AI・容量RPCへ接続しない。認証は既存の枠組みを利用する。
- `URENAVI_PRODUCT_INPUT_MODE=manual` のホストでは、旧検索（search/search-v2）、商品ジャンル取得（pro-genres）、キューを含むPro商品選定（pro/pro-cron）、旧生成・比較（room-ai/room-ai-v3）をサーバー側で拒否。手入力生成だけを開ける。アプリは楽天検索や既存商品結果の画面を隠す。既存のコード、キャッシュとキューは保持。フラグ未設定の環境では旧経路を維持。
- 直接の楽天API呼び出しは `api/search.js`、`api/pro-genres.js`、`lib/pro-search.js` と実験用 `lib/room-writer-raw/acquisition.js`。旧商品検索は取得結果を画面に渡し、Pro選定はキュー保存、旧生成は受領データや商品キャッシュに依存し得る。手入力はそれらを読み込まない。
- 手入力によるAPI非依存を検証した。利用者が入力する情報・画像・記載の権利、楽天ROOMや楽天アフィリエイトの条件、広告表示と取扱データ、ホストの商用プラン等の適合判断は残る。本番フラグ、決済、認証設定の変更は行っていない。

## 文章評価

商品理解と原文証拠・購入理由の抽出、既存公開判定を維持。公開判定が通った原文接続済み本文に対し、手入力のレンダラーが限定した重複表現を整える。決定的に再現できる編集結果だけを受け付け、条件・否定・程度・数値・対象の変更をテストで拒否する。任意の言い換えの同義判定には対応していない。

手入力APIの通信遮断テストで生成した全文は次のとおり。

> 電気ケトルは、細い注ぎ口により、湯の量や速度を初心者でも調整できます。
>
> 価格：3,980円
>
> ※アフィリエイト広告を利用しています

44商品と別枠18商品は以前の保存入力を使用。既存エンジンの出力を再現し、手入力のレンダラーを個別に比較した。回帰の生成候補15件・公開ゲート通過11件、別枠の生成候補8件・公開ゲート通過2件。回帰の1件のみ表現を短くしたが、6項目全合格には昇格させない。前回の判定を維持し、合格／不合格／未確認は44商品で3／12／29件、別枠18商品で0／8／10件。レンダリングが変わらない項目の評価は前回の保存評価を引き継いだ。独立人手評価とiPhone実機の検証は未実施。各出力は `replay.json`。

## 容量管理

v2 SQLは使い捨てPostgreSQL専用。プロバイダーと契約者それぞれの分・日窓についてリクエストとトークンを単一トランザクションで予約する。期限を迎えた枠は、新しい信頼済み窓情報が登録されるまで受付を拒否。確定した消費は予約時の窓に精算し、429や消費不明では予約を維持してプロバイダー全体を停止する。各プロバイダーの送信意図は同時に1件。重複したID・送信意図・精算を拒否する。

未接続の部分は、本番相当の残量証拠の取得、外部使用と台帳計上済み使用の分離、契約プランからの上限付与、窓の実計測基準と安全な停止解除、既存プロバイダーアダプターとの結線。v1と本番DBへの適用は行っていない。Groq・Gemini・楽天APIへの実通信0回。
