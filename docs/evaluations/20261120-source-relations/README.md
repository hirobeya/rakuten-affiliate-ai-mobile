## 文章品質

従来は利用者が明示した「場面・特徴・便益」の一文でも、メーカー原文に多い商品名の明示・既存候補パターンに合わず、商品と因果が結び付かなかった。利用者が単一商品に紐づけて書いた因果文から、商品主体、場面、特徴、便益を別の根拠スパンとして記録。対象者、条件、否定、程度、数字はスパン内で保持する。明示された因果接続を保って、商品名と利用場面を先に提示する。原文から再抽出したスパンと書き直し後の文を照合し、想定外の変更を拒否。別売り、断定、競合する記述などは遮断する。対象構文は限定的で、自由な説明からの因果推定や任意の言い換えには対応しない。

| 対象 | 出力前→後 | アシスタント評価の6項目合格／不合格／未確認 |
|---|---:|---:|
| 回帰44商品 | 11→11 | 3／12／29（据え置き） |
| 比較履歴18商品 | 2→2 | 0／8／10（据え置き） |
| 今回選んだ保存実商品8件 | 0→0 | 0／0／8 |
| 今回作成した手入力8件 | 0→5 | 4／1／3 |

軸は商品理解、特徴の具体性、購入理由、対象・場面・価値、自然さ・魅力、入力への忠実性。公開ゲート、テスト、アシスタント評価、独立人手評価は別。出力なしは6項目未確認とし、拒否理由を記録。独立人手評価なし。回帰44と履歴18の出力は全文一致し評価を継承。保存実商品8件は回帰・履歴にないケトル、収納、ペット用品、モバイル用品を保存済み検索原文から2件ずつ、固定SHA-256順で選定。基準コミットに商品IDがないことを確認したが、全過去実行履歴での未使用は未確認。8件のうち6件は購入理由を抽出できず、1件は商品主体が競合、1件は公開判定を通過できなかった。手入力8件は新規に作成した構文対応・否定例で、実商品の独立した品質証明には使用しない。入出力全文と評価は `comparison.json`。

## 容量管理・実機

v2 SQLと従来のプロバイダー実測証拠は保持。既存の契約者確認から得たIDを使い、v2の予約・送信直前の窓確認を含む送信意図・精算へ接続するサーバーアダプターを実装し、模擬応答で検証。未確定の送信意図は再試行せず、消費不明は既知消費として精算しない。手入力エンジンはこの経路に依存しない。ブラウザ試験の初回で旧検索セッションの復帰処理が残っていることが分かり、手入力モードではブラウザの復帰処理と商用候補ホストの旧復帰APIを遮断した。実際の容量証拠の同期、契約別上限の算定、停止解除、DBと稼働中の外部AI経路への結線は未実施。

隔離Previewの `/app.html?mode=manual` をiPhone Safariで開き、オーナーの既存ログインを確認する。商品名と説明を入力→「投稿文を作る」→「コピー」→「楽天ROOMを開く」→ROOMで対象商品を自分で選び、コメント欄に貼って一致を確認する。実投稿はテスト条件に含めない。Chromiumの検証は認証とROOM遷移先を模擬し、ローカルAPIで表示・クリップボード・遷移・通信先を確認する。iPhone実機とは別。
