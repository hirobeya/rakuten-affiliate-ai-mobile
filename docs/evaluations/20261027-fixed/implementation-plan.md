## 実装・ローカル検証
- 共有の拒否専用restatedReasonを、サーバーローカル、ブラウザローカル、コピー境界へ接続。固定した弱い4件はローカル完成から除外、対照5件は本文完全一致・追加Groq0で保持。原文自体は変更しない。
- 最初の「品名だけの独立文をすべて拒否」は、既存の具体的な機能理由を持つ正例も止めたため採用しなかった。用途の反復だけで品名を独立させた場合へ絞った。古いテストの構成数だけで合格という条件は固定所見に従い明示的に更新。ローカル正常経路の統合テストは実際の出し入れ関係を持つ原文で維持した。否定対照は品質で先に止まっていても競合検出そのものを追加確認する。
- 既存reviewの重複指示を統合。5問・品質6項目・全原文・全本文・引用・unclear拒否・出力上限3000・モデルは保持。保存草稿38組の審査見積もり8000超過は15→9で、まだ全工程容量成立とは扱わない。capacityの結果は推計であり実トークンではない。
- 固定草稿だけを既存reviewへ通すQA経路を、既存Function内の別フラグへ隔離。Preview/owner限定、未知フィールドや任意の草稿・prompt/modelの入力を拒否。共有予算、既存quota、送信済み不明消費保護、単一送信、結果キャッシュを使用。通常の生成回数は増やさず、実験結果はpublishable:falseを固定する。DB/RLS/認証設定を変更しない。
