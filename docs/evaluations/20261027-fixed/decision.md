## 切り分けた問題

### 1. ローカル判定が「特徴の言い直し」を完成扱いにする

現行44件からreadyとなる9件中、少なくとも次の4件に単独評価上の問題を記録した。ほか5件を自動的に全品質合格へ数えてはいない。

- フライパン：「キッチンでの調理に。IHでの調理に対応。フライパンです。」用途の反復と品名だけの独立文。
- 収納ボックス：「折りたためる形で選びたいとき。折りたたみ仕様の収納ボックスです。」特徴の言い直し。
- バイクグローブ：「停車中にスマホ操作もしたいとき。スマホ対応のバイクグローブです。」使用意図と対応ラベルの言い直しに留まる。
- 6枚セット洗濯ネット：サイズ組み合わせ自由という説明だけで、具体的な意図との接続がない。

コードでは `localZeroCall` が候補の存在・根拠・安全性・特定の定型語の拒否を経てreadyとする。`hasChoiceRelation` は組み合わせ自由と選べるセット数を検出するが、そのことだけでは独立6項目の選ぶ理由を証明しない。`catalogueOnly` は禁止した言い回しを検出する拒否器であり、通過は魅力の証明ではない。辞書に商品を足すだけでは解決しない。

### 2. 保存AIのsupportedにも弱い文章がある

保存されたipowと6枚セットの文章は、AI品質6欄がsupportedで、現行再照合でもreadyになる。一方、当時の単独評価と今回の予備所見では、一般的な説明・便利という評価に留まる。AIがsupportedを返したことを、そのまま独立した魅力合格として使えない。

### 3. 本物の失敗と誤った拒否理由が併存する

商品名にブラジャーネットがあるのに、保存AI審査が対象不在を理由に拒否した例を確認した。しかし、その審査には別に原文外の引用もある。誤った理由を一つ見つけても、拒否全体を解除してはいけない。

固定草稿では商品種別の本文欠落が11組で検出された。単位・引用・程度の拒否も残る。この結果を、すべて過剰検査のせいにはできない。

### 4. 初稿だけの容量確認では足りない

原文・草稿・失敗理由を保持すると、AI審査15組、再作成16組で現行安全見積もりが観測8,000を超える。長文を切る、出力上限を黙って下げる、予算保護を外す、無断で別モデルへ変えることで通過させない。

## 次の有限な実施範囲

既存設計のP2/P3に戻り、既存エンジン内で「本体/対象/型 → 根拠 → 特徴を選ぶ具体的意図 → 実際の本文」を同じ情報で照合する影比較へ絞る。新しい生成器・常設AI工程・商品別例外・本番への公開切替は追加しない。

1. この固定集合で、良い3例・弱いready・重大な安全負例を分けた評価記録を作る。2名盲検の評価者一致と相違は別途必要。単独所見で代用しない。
2. ローカル候補の「仕様がある」と「本文で選ぶ理由が成立する」を分離する影比較を行う。弱いreadyの識別、良例の保持、安全負例の拒否を同時に示す。readyを全部なくした結果を改善とはしない。
3. AI審査は同一草稿への比較に限定し、対象不在・条件・程度・引用のどこが変わったかを記録する。文章を再生成してから審査を比較しない。
4. 原文と既存の検証契約を保持した全工程の容量を計測する。成立しない入力は明示する。全時間窓・利用者別予算・不明usage復旧を証明せず、30人提供可能とは判定しない。
5. オフラインで改善しない変更は採用しない。改善が示されたものだけ少量実通信へ進める。固定した本文の正しさ・購入理由・使用量を比較し、同じ失敗商品の無意味な再生成を続けない。
