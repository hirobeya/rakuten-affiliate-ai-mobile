## 比較条件と評価

20件すべての入力を固定インデックスの順序、商品コード、カテゴリ、商品名・原文本文・入力価格のSHA-256で確認する。比較時の未固定メタデータ、catchcopy、リンク・登録情報は除外。B/Cの書き手に送るのは商品名と全文説明だけで、Cのみ既存台帳の原文根拠を追加する。反実仮想の追加情報や暗黙の関連知識、商品別の調整、事後の商品選択を行わない。Cに根拠がなくBと同じ条件になる場合は比較に計上せず、重複送信を行わない。

B/C共通で `openai/gpt-oss-120b`、chat、temperature 0.2、reasoning medium、JSON Schema strict、最大出力は書き手・審査各2,000。承認後の上限は方式と商品ごとに書き手1回、公開判定の機械審査を通った場合だけ別の審査1回。同一モデルによる別審査であって、人手による独立評価を意味しない。既存の否定・数値・部位・安全・根拠審査を変更していない。

商品別評価は商品理解、特徴の具体性、選ぶ理由、場面と価値、日本語の自然さ・魅力、原文への正確性。一つでも既知の不合格があれば全体不合格、すべて合格の場合だけ全体合格。評価者区分、判断根拠、本文ハッシュを別に保存する。AIの審査は公開ゲートの一部として扱い、商用品質の6項目を自動で合格にしない。今後の人手評価では方式名を隠し、価格・広告フッターを文章評価の採点対象から除外する。

## 再現と次回実測

通信禁止ガード下で固定原文JSONから実行する。原文は作業中の保存データを使用し、新規にGitへ転載しない。

```sh
bash scripts/rebuild/offline.sh scripts/rebuild/compare-generation.cjs \
  --inputs /path/to/frozen-originals.json \
  --evaluations docs/evaluations/20261120-ai-comparison/assistant-evaluations.json \
  --rates docs/evaluations/20261120-ai-comparison/public-rate-example.json \
  --out /path/to/comparison.json
```

`--item` と `--arm B|C` を追加すると、承認対象の送信本文・SHA・予約量・安定した試行IDを書き出す。これは送信機能ではない。機械審査を通った書き手出力の記録に限り `--writer-receipt` で検証リクエストを構築できる。書き手記録には itemCode、arm、sourceHash、model、writerRequestHash、draft が必要。照合済み保管結果の再評価は `--receipts` で配列を渡し、検証記録の reviewModel、reviewRequestHash、review、各stageの使用量と時間は writerUsage／reviewUsage の input・output・elapsedMs に保存する。ハッシュ一致は再現条件を確認するもので、実通信の事実は別途監査記録が必要。

| 実測範囲 | 書き手＋審査の最大通信 | 予約量の合計目安 | 公開単価での概算上限 |
|---|---:|---:|---:|
| B20件 | 20＋20＝40 | 285,298 | US$0.0787947 |
| C2件 | 2＋2＝4 | 29,753 | US$0.00806295 |
| 全体 | 22＋22＝44 | 315,051 | US$0.08685765 |
| 最初に比較可能な同一2商品でB/C | 4＋4＝8 | 58,460 | US$0.015969 |

同一2商品は e-kurashi:10037463 と e-kurashi:10018414。書き手の見積予約量に、審査1回あたり8,000の参照上限を加えた値。審査は実際の書き手出力と原文を揃えて送信直前に再計算し、8,000超過なら停止する。実残量を示す数値ではない。Groq公開単価 US$0.15入力／US$0.60出力（100万トークンごと）を適用した費用の見積上限であり、請求の保証ではない。全部を一度に予約せず、RPM/RPD/TPM/TPDの最新残量・リセット・契約別枠を各段階で判定する。過去に確認したTPD 200,000を上限とするなら315,051は一日の予約上限を超える。実測値での消費と最新の利用可能残量は別に記録する。

次回承認は最終SHA、比較ID、対象ID、方式、モデル、出力上限、書き手のリクエストSHA、審査への移行条件、通信回数・費用の上限を明記する。実行側に新鮮な残量証拠と容量管理v2の確定した予約・送信意図・精算を組み合わせ、エンベロープIDで方式と段階を分ける。429、失敗・消費不明、保存不明、期限切れ時に停止し、自動再試行を行わない。今回のCLIには送信器を含めず、既存のオンライン経路にも比較実行を接続していない。

## 採用と商用

Aは費用面で軽いが、固定実商品で全6項目合格1/20のため販売品質を証明できていない。B/Cは、同じ商品に対する実生成・機械拒否・別審査・人手評価、トークン費用・待ち時間の証拠が必要。Cは今回2/20に絞られ、B/Cの結果はこの2件の対応比較とB全20件の単独結果として扱う。AIが有効と実証できた場合に、Aで品質を満たさない商品のみAIを使う費用設計を比較する。商用採用には楽天ROOM・アフィリエイト規約、Vercel商用条件、月額1,480円の実契約と採算、iPhone実機の確認が引き続き必要。今回は販売条件の変更なし。
