# ウレナビ 商品説明の文・項目をまたぐ根拠比較

基準 PR #184、GitHub SHA `6d66dcde3867822c1425b24b4cafc8a5cf41382a`。文章のみを比較。楽天API、Groq、Geminiへの実通信は0回。

## 実装

句点、改行、箇条書き、説明・仕様・注意等の節を分解し、前処理で原文位置を失わない共通処理を追加した。既存の原文台帳と手入力の因果解析は同じ分解処理を使う。新しい購入理由候補は商品主体、明示特徴、範囲、使用対象、明示便益、原文位置と引用、対象者・条件・数値・否定・程度の手掛かりを保持する。

商品説明中の項目は、タイトル中の確定商品主体と説明見出しから帰属を確認する。複数文の因果は直前の単独の機能文を明示接続語で受けたものに限る。単なる隣接、別商品、別売、別モデル、未確定の型式や条件は根拠にしない。商品名と根拠を照合し、型で許された語順・述語の変更だけで購入理由を構成する。従来の拒否判定を適用し、文の長さと購入理由の具体性の評価は別に行う。比較対象が不明な「より長持ち」は旧経路からの出力も拒否した。

複数文を明示接続語で結ぶ経路は合成ケースで成立。実商品の新規2件では、複数の説明箇所（宣言・見出し・該当箇条書き）を使って商品への帰属を確定した。購入理由そのものは各箇条書きに明記されていた。曖昧な離れた文章に書かれた便益を、複数文から一般的に推定できた証拠はない。

## 採用とAI比較

商品帰属の確認と明示関係に限った文章生成を手入力経路に採用。多段の照応や根拠を確定できない説明をローカル構文規則で埋める方式は採用していない。この残りは、次の承認済み比較で同じ固定原文を用い、既存の書き手と検証ステージに、どの引用がどの商品・便益に属するかを提示する方式を比較する。

既存のGroq書き手向けJSONに、同じ原文スパンを付ける仕組みを接続した。ヒントは公開承認を付与せず、既存の入力・出力予算を超える場合は送信用ペイロードから外れる。通信なしの比較準備では、書き手1回の見積最大 tokens と確認済み残量を比較し、価格根拠がある場合のみ、入力・出力単価の高い方で費用上限を積算する。検証ステージを行う場合は別枠の予算を要する。価格・現在残量の実数は未確認。計算は通信・予約・解放を行わず、容量管理v2と停止条件を保持する。
