# 全ジャンル共通の購入理由と最終コピー整合（2026-10-21）

## 範囲と基準

既存 Preview ブランチの文章品質を改善する。商品別の辞書追加や第二の生成器は作らない。商品名・説明・catchcopyを入力にする既存の生成→原文照合→意味検証→最終コピーの経路を維持する。main、Production、決済、PRのDraft状態は変更しない。

原文にある特徴と、具体的な使用意図との関係を文章の中心にする。機能だけでなく香り・内容・包装なども扱い、未登録カテゴリは既存の意味生成経路へ送る。全商品で同じ処理・判定を使うことと、全商品の購入意欲を実証したことは異なる。資料に選ぶ理由がない場合、体験・感情・効能・優位性を捏造しない。

## 変更

- writerとreviewerへ全カテゴリ共通の関係性の基準を追加。数値・素材と通常用途に「手軽」を接続しただけで完成扱いにしない。固定の悩み訴求や疑問形も要求しない。
- 共通のpurchase-copy-qualityは「仕様を見て選ぶ」「〜表記の商品」等の編集用の文を拒否する。これは品質の必要条件であり、正規表現で購入意欲を証明する機能ではない。意味による購入理由の審査は既存reviewerが担う。
- 安全なcaptionの完全な使用関係を、題名の仕様ラベルより優先する。原文に関係が完成している場合、辞書の汎用的な導入句を足さない。関連商品・付属品・否定・危険表現・販促文の除外を維持する。「8枚なので大変お得」も取り込まない。
- localの完成判定、structuredの判定、semanticの機械検査、ブラウザーの最終コピーで同じ拒否条件を使用。旧い弱いキャッシュを使わないようsemantic版ハッシュへ共通モジュールを含める。
- 短いlocal本文はserverの完成結果、本文とvariantの完全一致、local/0calls、caption_claim、原文引用の存在・関係を必要とする。最終の既存事実安全ガードは引き続き必須。booleanだけでは短文を承認しない。
- 機械検査で弱い草稿を止めた場合も既存の一回限りの全文推敲を使う。生成schema、対象・部分・条件・否定・程度の5問、曖昧なら拒否する方針は変更しない。

## 呼び出し制御

無料Groq、共有残量予約、原文に一致した完成キャッシュの再利用、1回の推敲上限、429時の全体停止、時刻経過だけでAPI再試行しない制御を維持する。品質で不十分なlocal草稿をAIへ送るため、旧版よりlocal完成率が下がるケースはある。これを隠すために品質を戻したり商品別例外を足したりしない。

## 回帰検証

既存の780商品コーパスの引用・factRefs・安全ガード検査を維持。お茶・手芸・本・ギフト用品・調整台で共通source候補処理を検査し、未知商品の弱い草稿→既存推敲→5問審査→画面コピー→0callsキャッシュを模擬した統合テストを追加。これは実Groq品質の承認とは区別する。

旧テストのうち「型崩れ防止という表記です」「容量を見て選ぶ」といった草稿を完成扱いにしていた期待値を修正した。元の引用・数値重複除去・否定・関連商品の境界テストは保持。布団の入る大容量や二重ネットで形を維持する原文の具体的な関係は引き続きlocal/0callsで完成できる。
