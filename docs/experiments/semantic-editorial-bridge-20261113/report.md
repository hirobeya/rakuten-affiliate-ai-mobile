# ウレナビ｜意味理解型文章生成への接続実験（2026-11-13）

## 判断

以前の失敗は、魅力が弱いたびに文章テンプレートや検証例外を増やしたこと、および原文の販売単位・条件を理解する前にコピーを作ろうとしたことにある。

既存資産を再利用：
- `lib/room-writer-raw/source.js` は楽天原文を切断しない。
- `lib/room-writer-raw/contract-v2.js` には商品全体の理解・セット条件・注意事項・根拠付きStrict JSONの既存契約がある。
- PR #172 の `buyer-decision-plan.js` は、原文根拠に紐づく複数の選択理由を保留付きで整理する。

**今回追加したのは文章生成テンプレートではなく、既存のAI全文理解経路へ購入理由候補を受け渡す検証用接続部分だけ**である。

## 実装

`lib/urenavi-core/semantic-editorial-bridge.js` に `prepareSemanticComparison(item,{identity})` を実装。
- 既存V2契約の `model`, `reasoning_effort`, `max_completion_tokens`, `response_format` を変更せず再利用する。
- 原文を全文保持。商品情報は `productData`、購入理由候補は `editorialDecisionAid` に別格納。候補・使用場面は商品事実ではないと明示。
- 原文引用・原文位置・販売単位未認証を検証し、元原文と異なる判断を推奨しない。
- 重複するAI指示を追加せず、購買理由を自然文へ変換する編集意図だけを付加。
- **API送信関数なし、鍵取得なし、自動再試行なし、公開不可・コピー不可・認証未完了**。本番、main、既存Groq監査原本は変更なし。
- 推定TPMが8,000超または余裕500未満なら保留。ただし推定値が余裕を持っていてもGroq実測の利用可能残量を保証するものではない。

## テスト

- `node --test tests/room-writer-raw/*.test.js`：111/111成功
- `semantic-editorial-bridge.test.js`：原文完全性、旧JSON Schema不変、元リクエストhash不変、関連商品・誤同定拒否、購入根拠不足による保留、通信余裕不足による保留
- 未知商品への文章品質の再現性やAIの生成品質は**未測定**。

## 完成までに何が必要か

1. このオフライン比較用リクエストで実際にAIがどう説明文を作るか、権限・使用枠・通信条件が整った場合のみ**限定実測**する。過去のGroq `json_validate_failed`、`max_completion_tokens=1000` 到達、free TPMを踏まえ、追加通信は別途承認を要する。
2. 実測結果を6品質軸（商品理解・特徴具体性・購入理由・対象場面と価値・自然さと魅力・根拠外0）で人の独立評価と原文照合にかける。
3. 通信枠が不足する商品を原文切断で救済しない。より少ない予算で意味理解と文章品質を維持できる契約を実測比較する必要がある。
4. 未見の商品・モデル違い・関連商品の誤混入を含め再現性を確認し、合格後にのみ本体統合とiPhone実機/別契約者テストへ進む。

**判定**：既存システムを壊さず、意味理解による文章生成方式を比較する入力を2商品について準備できた。しかし最終的な文章の魅力はまだ証明できない。ウレナビの完成・本番採用は認めない。
