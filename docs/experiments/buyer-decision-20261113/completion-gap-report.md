# ウレナビ完成への技術判断と不足構成の確定（2026-11-13）

## 結論

主要機能や安全装置を新しく積み直すことは不要。文章品質の阻害要因は「確認済み商品特徴」から「その特徴に価値を見いだす利用場面・購入判断」へ移行する明示的な意味計画がないこと。

PR #169 は根拠付き特徴抽出、PR #170 は特徴起点の自然文、PR #171 は生活場面起点の文を実証したが、いずれも文章の魅力は未合格・未認証。固定フレーズや例外を重ねる方式は採用しない。

## 今回の新規最小実装

`lib/urenavi-core/buyer-decision-plan.js`

- 既存`grounded-local-recovery.js`から原文引用と位置を読み、引用の一致を再検証。
- 商品固有のキーワード別コピー文を作らず、収納・手入れ・給電・用途などの**購入判断の関係グループ**だけを組み立てる。
- 複数の独立した特徴が同じ購入判断に結び付いているかで強さを分ける。注意・条件は利点と混同しない。
- 購入場面は`hypotheticalScene`に分離し、「販売者が書いた商品事実」ではないと明示。
- `getDecisionKnowledge`の有無を記録する。知識を商品原文の証拠としては使わない。
- `publication:false`、`copyable:false`、`semanticApproved:false`、販売モデル属性未照合を固定。既存アプリへ組み込まない。

## 完成までの残務（順序固定）

1. **購入理由の意味検証**：関係グループが実際に原文の販売商品に属するか、否定条件・セット種別・関連商品の混入を商品横断で検証。単なる引用一致で認証しない。
2. **文章表現の比較**：完成度が証明された中間表現だけを使用し、説明の羅列・見当違いのベネフィットを排除。新しい定型パターンを増殖させない。
3. **未見商品と独立レビュー**：最低限、既存4商品と未見の異なるカテゴリ商品を分けて同じ6軸基準で評価する。未検証を不合格と混同しない。
4. **本体統合**：既存の安全装置と認証・決済を保持したまま隔離Previewで検証。iPhone一連操作と別契約者の権限分離を確認後にだけ公開判断。
5. **Groq最終手段**：独自文で実測不合格時に限って比較。実Groq通信は別途承認境界を守る。

## 技術的判断

これ以上、過去の4商品だけに合わせたテンプレート修正はしない。「4商品の文章が出せる」と「契約者がどの商品でも魅力ある文を得られる」は別の課題。

現時点では完成と断定できない。今回の成果は、文章生成に先立つ購入理由の強弱を根拠つきで切り分けられること。
