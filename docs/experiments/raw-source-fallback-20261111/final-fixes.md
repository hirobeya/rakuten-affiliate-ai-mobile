## 3. 容量と初回1通信契約

以下を別々の項目として保存する。

- **公式上限**: モデル、有効なRPM/RPD/TPM/TPD、確認時刻。上限値を残量として使わない。
- **観測使用量**: 観測元、完全/部分、対象期間・window、確認時刻、通信回数、入力/出力/合計トークン。残量へ変換しない。
- **残容量**: 分間トークン、日次トークン、日次リクエストを独立させ、不明値は明示的null。未指定や推定値を代入しない。
- **独立実験予算**: v2新台帳の予算、送信記録数、実際の消費量、分間使用量。一度限りの要求予約は推定であり実測残量ではない。
- **排他・不明消費・重複**: 使用量不明の未確定要求がないこと、排他、過去商品・同一商品の再送禁止、送信前の永続記録。

現期間内の観測済み消費だけで上限不足になる場合は、初回モードでも拒否。過去期間の合計を現在使用量に読み替えず、観測元と期間を記録する。既知の残量不足は不明残量承認でも上書きできない。

### 独立した初回専用モード

承認version: `raw-source-fallback-initial-v1`。通常モードの残容量欠落から自動選択しない。

必要な承認対象:

1. 新ルートの実行SHA、隔離実験環境。
2. 商品原文sourceHash、送信requestHash、明示的不合格のqualityHash。
3. 新規v2台帳のexperimentIdとauditId（パスのハッシュ）。別台帳へ持ち込めない。
4. 最大生成1通信・実験全体最大1通信・自動再送0・60秒以内の有効期限。
5. 推定入力＋出力上限2,000を含むmaxReservedTokens。独立予算・有効TPM上限以下。
6. `unknownCapacityPolicy=retain_null_one_call` と `acceptUnknownCapacity=true` の新たな明示承認。

既知の不足、未確定通信、排他なし、古い観測、未確認使用量、予算不足は例外にしない。unknownの残量を0/満額へ補完しない。予約は推定で、プロバイダの実入力計数と完全に一致する保証ではない。実測が予約を超えた場合も停止・再送禁止。

承認対象を作る `initialApprovalTarget` は `authorized=false`、リスク受容false、期限nullの非承認テンプレートを返すだけ。品質未確認や不合格未確定の結果には対象も作らない。今回、実行可能な承認は発行していない。

### 保存と停止

- 新しい `raw-source-fallback-v2` ディレクトリへ新manifestを作る。旧v1/S3台帳の移行・精算・解放はない。
- 排他ロックと `initial.once.json` をwx/fsyncで送信前に保存し、実行SHA・承認ハッシュ・公式上限・観測使用量・不明残量・原文・要求ハッシュを要求記録へ保存する。
- 保存中に承認・観測期限が切れたら送信しない。送っていないことを記録し、一度限りのマーカーは解放しない。
- 通信は最大1回。429、結果不明、使用量不明、JSON失敗、予約超過、保存失敗は停止。自動再送しない。
- 初回では応答後の日次残量等が不明でも、その事実を保持。実際の応答と使用量が分かれば全文と検証結果を保存する。
- 成功時も `initial_probe_complete_review_required` で停止し、マーカーを保持。別商品や通常モードの承認を使って同じ実験を継続できない。
- 旧S3承認・旧PR166初版live-v1承認・旧環境フラグは受け付けない。旧S3原本の参照は再送拒否と回帰だけで、初回許可や残容量の根拠へ取り込まない。
