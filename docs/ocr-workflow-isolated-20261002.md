# API不使用ルートの独立試作

入口: `/ocr-workflow.html`。通常版、Pro、既存workflow-prototype、shortcut-prototypeは残す。
API呼び出しは既存room-aiのpreview owner専用 `mode: ocr_workflow` のみ。ocr_textと通常生成は従来の処理を維持する。

テーマ・用途・予算→楽天検索画面→利用者の端末内OCR文字取り込み→最大3候補比較→選び直し→原文・仕様・購入条件の確認→選択仕様による文案→編集・コピー・ROOM移動・端末内履歴。
無料枠のAIを候補の構造化に1回使用。文案作成に既存生成器を1回使用、選び直し自体にはAI呼び出しなし。追加Function・DB・有料依存なし。手入力は利用者のfallbackであり、ヒロの運営作業ではない。

AIの候補ごとのsourceTextを入力原文と完全一致照合。商品名・比較項目・factsをその範囲で照合。検証不能な情報は除去する。原文照合は商品の正しさやOCR精度を保証しないため利用者が商品ページで確認する。用途適合・向かない条件の自動断定は未実装。
出力文案は既存生成器の許可された一段便益を使用。無料枠上限・失敗時は仕様列挙型へ戻す。暮らしの具体的な便益の実出力評価は未完了。商品発見には利用者の楽天画面操作が必要。元のウレナビ以上の価値・ChatGPTより短時間は未実証。

検証: 新規8ケース、既存test:ai、vercel-build成功。認証付きGroq実測、iPhoneショートカット実機、OTPM測定、商用無料ホスティングは未確認。販売開始・main merge・Production反映は行わない。
